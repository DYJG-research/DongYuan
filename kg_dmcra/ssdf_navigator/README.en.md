# SSDF-Navigator: Active Information Acquisition Engine of DongYuan

The **SSDF-Navigator** instantiates the **Domain-Knowledge-Grounded Active Information Acquisition (DK-AIA)** paradigm as the active information acquisition engine within the **KG-DMCRA** of the **DongYuan** medical expert system. It is a lightweight Transformer-based policy model trained from authentic physician-patient dialogues for multi-turn proactive consultation in ICWM (Integrative Chinese and Western Medicine) spleen-stomach disorders diagnosis.

> **📌 This module is part of the [DongYuan](https://github.com/your-org/DongYuan) project.**  
> Refer to the [root README](../../README.md) for the full system overview and architecture.

## The Four Design Principles of DK-AIA

SSDF-Navigator follows four transferable design principles proposed by DK-AIA as a general paradigm for active information acquisition in clinically complex medical expert systems.

### 1. Ontology-Embedded State Abstraction

Raw interaction histories are expressed in unstructured natural language, where semantically similar inputs take diverse lexical and syntactic forms. To address this, DK-AIA maps interaction trajectories into a **structured state space** $\mathcal{S} = \{s_1, s_2, \dots, s_N\}$, where each state corresponds to a standardized domain information unit.

For an interaction episode with $t$ acquisition steps, the raw history is mapped to a state sequence $\mathbf{s} = [s_0, s_1, \dots, s_t]$. A **sliding window of length $L$** constructs the decision state:

$$\text{state}_t = [s_{t-L+1}, \dots, s_t]$$

The policy is defined as:

$$a_t \sim \pi(\cdot \mid \text{state}_t)$$

where $a_t = s_{t+1} \in \mathcal{S}$ is the next standardized information unit to acquire.

### 2. Information-Gain-Driven Reward Shaping

**State transition probabilities** are estimated from offline historical data with Laplace smoothing:

$$P(y \mid x) = \frac{C(x, y) + \alpha}{C(x) + \alpha \cdot N}$$

where $C(x, y)$ is the co-occurrence frequency of $x$ and $y$, $C(x)$ is the total frequency of state $x$, $N = |\mathcal{S}|$ is the state space size, and $\alpha$ is the Laplace smoothing factor.

**Normalized conditional entropy** quantifies remaining uncertainty after querying symptom $x$:

$$\tilde{H}(Y \mid x) = \frac{H(Y \mid x)}{\log N} = -\frac{1}{\log N} \sum_{y} P(y \mid x) \log P(y \mid x)$$

**Information gain reward**:

$$R_{\text{info}}(a) = 1 - \tilde{H}(Y \mid a)$$

**Repetition factor** $\lambda(a, \mathcal{H})$ penalizes redundancy while allowing necessary key symptom revisits:

$$\lambda(a, \mathcal{H}) = 
\begin{cases} 
0.3 & \text{immediate repetition (same as previous query)} \\
1.5 & \text{delayed revisit (non-consecutive key symptom)} \\
1.0 & \text{neutral (new symptom query)}
\end{cases}$$

**Final immediate reward** (scaled to match BC loss magnitude):

$$r_t = R_{\text{info}}(a) \cdot \lambda(a, \mathcal{H}) \cdot K, \quad K = 2.0 / 1.5$$

### 3. Hybrid Imitation-Reinforcement Policy Learning

Two hybrid training schemes are proposed:

#### Reward-Weighted Behavior Cloning (RWBC)

Reweights the behavior-cloning loss by immediate reward, giving greater emphasis to expert actions associated with higher information gain:

$$\mathcal{L}_{\text{RWBC}}(\theta) = -\frac{1}{B} \sum_{i=1}^{B} r_t \cdot \log \pi_{\theta}(a_t^* \mid X_t)$$

Implemented with `--fusion_mode mul`.

#### Reward-Added Behavior Cloning (RABC)

A weighted sum of three terms — behavioral cloning loss, policy gradient loss, and entropy regularization:

$$\mathcal{L}_{\text{RABC}}(\theta) = \beta_1 \mathcal{L}_{\text{BC}} + \beta_2 \mathcal{L}_{\text{PG}} + \eta \mathcal{L}_{\text{Ent}}$$

where:
- $\mathcal{L}_{\text{BC}}(\theta) = -\frac{1}{B} \sum \log \pi_{\theta}(a_t^* \mid X_t)$ — supervised behavioral cloning
- $\mathcal{L}_{\text{PG}}(\theta) = -\frac{1}{B} \sum A_t \cdot \log \pi_{\theta}(a_t \mid X_t)$ — policy gradient with advantage $A_t = r_t - b$
- $\mathcal{L}_{\text{Ent}}(\theta) = -\sum_a \pi_{\theta}(a \mid \text{state}) \log \pi_{\theta}(a \mid \text{state})$ — entropy regularization for exploration
- $\beta_1, \beta_2$ — balancing weights; $\eta$ — entropy coefficient

Implemented with `--fusion_mode add`.

### 4. Dual-Module Candidate-Based Coordination

To integrate the active acquisition policy with SSDF-Core (the deep diagnostic reasoning engine) within KG-DMCRA:

1. The structured history queue $\mathcal{H}_0$ starts empty; the first interaction is generated by SSDF-Core
2. From the second timestep onward, SSDF-Navigator is activated only when the previous interaction can be mapped to the structured state space and $\mathcal{H}$ is non-empty
3. SSDF-Navigator predicts a probability distribution and converts **top-$K$ predictions** into standardized candidate actions: $\mathcal{A}_{\text{ia}} = \{a_1, \dots, a_K\}$
4. SSDF-Core independently generates a candidate interaction in natural language, mapped to $a_{\text{core}}$
5. The next action is selected by SSDF-Core from the **combined candidate set** $\mathcal{A}_{\text{ia}} \cup \{a_{\text{core}}\}$ according to the current context and reasoning path
6. Consultation terminates upon **information saturation** (new inquiries repeatedly map to symptoms already in the history queue) or a **hard limit of 30 dialogue turns**

## Implementation in ICWM Spleen-Stomach Disorders Diagnosis

DK-AIA is instantiated as **SSDF-Navigator** (shown in Fig. 4 of the paper), a lightweight policy model for multi-turn proactive consultation:

- **Architecture**: Transformer-based encoder-classifier
- **Input**: Structured symptom history queue (recent $L$ symptoms)
- **Output**: Probability distribution over 83 standardized core symptoms
- **Standardized ontology**: Mapped from the national standard *Clinic Terminology of Traditional Chinese Medical Diagnosis and Treatment — Part 2: Syndromes/Patterns*, covering core symptoms for spleen-stomach disorders including epigastric pain, distension, discomfort, acid regurgitation, belching, and poor appetite
- **Training data**: Symptoms mapped from physician-inquiry questions in the spleen-stomach subset of **SSDF-Dialogue**; each dialogue case converted to a symptom state sequence; state-action transition samples extracted via fixed-length sliding window
- **Optimization**: Trained using either RWBC (Eq. 10) or RABC (Eq. 11) on the transition samples

## Quick Start

### Prerequisites

```bash
Python 3.10+
PyTorch ≥ 2.0
```

### Training

```bash
cd kg_dmcra/ssdf_navigator

# RWBC mode (Reward-Weighted Behavior Cloning)
python train_navigator.py \
  --question_file ./data/question_cleaned.csv \
  --symptom_file ./data/symptoms.csv \
  --fusion_mode mul \
  --max_seq_len 10 \
  --batch_size 64 \
  --epochs 100 \
  --lr 1e-4 \
  --save_path ./models/transformer_policy.pth \
  --gpu 0

# RABC mode (Reward-Added Behavior Cloning)
python train_navigator.py \
  --fusion_mode add \
  --lambda_supervised 1.0 \
  --lambda_reinforce 0.5 \
  --entropy_coef 0.01 \
  # ... other args as above
```

### Evaluation

```bash
python evaluate_navigator.py \
  --question_file ./data/question_cleaned.csv \
  --symptom_file ./data/symptoms.csv \
  --model_path ./models/transformer_policy.pth \
  --topk 5 \
  --eval_split val \
  --gpu 0
```

### API Service Deployment

```bash
cd ssdf_bench/mpc_evaluation
python navigator_api_service.py \
  --port 8999 \
  --model_path /path/to/transformer_policy.pth \
  --question-file ./data/question_cleaned.csv \
  --symptom-file ./data/symptoms.csv
```
